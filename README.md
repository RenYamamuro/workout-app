# 筋トレ記録アプリ（v1）

エニタイムフィットネス船橋二和東店の設備に合わせた A/B/C 3分割メニューを、
その場で記録するための自分用Webアプリ。素の HTML + CSS + JavaScript の1ファイル構成で、
データはブラウザの `localStorage` に保存される（サーバー不要・ログイン不要）。

## できること（MVP）

1. **メニュー選択** — A → B → C の循環。前回の記録から「次はこれ」を自動表示
2. **記録** — 種目ごとに重量とレップ数を入力して保存。セットの追加・削除も可能
3. **前回の記録を種目の横に表示** ← 本体。重量の初期値も前回値が入る
   - 重量は **− / ＋ ボタン**で 増減できる。刻み幅は種目ごとに
     1 / 2.5 / 5 / 10 / 20kg から選べる（カード右下の「刻み」をタップで切り替え）
   - まだ回数を入れていない後続セットが同じ重量なら、まとめて追従する

4. **記録の編集・再保存** — 履歴の各記録に鉛筆アイコン（編集）がある。押すと記録画面が
   その内容で開き、直して「この内容で更新」で上書きできる。間違えて保存してしまったときの
   修正用。「前回」「自己ベスト」の表示は編集中の記録自身を除外して計算するので、
   自分自身と比較してしまうことはない。保存せずに離れれば元のデータは変わらない
5. **推定1RMと自己ベスト** — 入力中のセットから Epley式（`1RM = 重量 ×(1 + レップ/30)`）で
   推定し、過去の自己ベストと比較する。無理に1RMを実測せずに伸びを追うため。
   `ratio: true` を付けた種目（スミスベンチ・V-スクワット・レッグプレス）では体重比も出す。
   体重は「データ」カードで設定（`workout-bodyweight-v1`、初期値58kg）
6. **データの書き出し／読み込み** — JSONファイルでバックアップ。端末やブラウザを移るときにも使う
7. **種目ごとの図解** — 19種目それぞれにマシンの図（SVG）を表示。タップで拡大
8. **種目ごとの履歴** — 図解をタップすると、その種目だけの記録が新しい順に並ぶ。
   推定1RMと自己ベスト（★）付き。履歴画面の種目名からも開ける。
   図解は小さく表示され、タップすると拡大する（履歴を主役にするため）
9. **実物の写真を登録** — 拡大表示から自分で撮った写真を登録すると、図の代わりに表示される

保存・書き出し・読み込みは、画面下に短い通知（トースト）で結果を知らせる。
アプリを止めない情報は `alert` を使わず通知に寄せ、`alert` はエラーだけに使う。

おまけ：
- 目標レップを全セット達成すると「次回は2.5〜5kg上げてOK」と表示（漸進性過負荷の判断用）
- 履歴一覧（日付・メニュー・総挙上量・メモ）と、記録の削除

### 図解と写真について

図解は手描きのSVG（`index.html` の `ART`）で、外部の画像は一切読み込んでいない。
灰色＝マシンの骨格、白＝人、青＝動く部分・負荷 という描き分け。

実物の写真はジムで撮って登録するのが一番わかりやすい。登録した写真は
長辺640pxのJPEGに縮小してから `localStorage`（キー `workout-photos-v1`）に保存される。
容量は全体で5MB程度が上限なので、入りきらない場合は使わない種目の写真を削除する。

## 公開URL

https://renyamamuro.github.io/workout-app/

OS・ブラウザを問わず開ける。更新は `git push` するだけで反映される（反映まで数十秒）。

**更新を端末に届ける方法**: iPhoneならアプリスイッチャーで上スワイプして完全に終了させ、
オンライン状態で開き直す。ホーム画面に戻すだけでは終了していないので更新されない。
GitHub Pages は `Cache-Control: max-age=600` を返すため、`sw.js` 側で
HTML/JS/JSON のリクエストに `cache: "reload"` を付けてHTTPキャッシュを迂回している。
届いたかどうかは「データ」カード下部の **アプリの版**（`APP_VERSION`）で確認できる。
デプロイのたびに `index.html` の `APP_VERSION` を上げること。

### ホーム画面 / デスクトップに追加

- **iPhone (Safari)** — 共有ボタン → 「ホーム画面に追加」
- **Android (Chrome)** — メニュー → 「ホーム画面に追加」
- **PC (Chrome / Edge)** — アドレスバー右のインストールアイコン

追加するとアドレスバーなしで起動し、Service Worker のおかげで
**オフラインでも開ける**（ジムの電波が悪くても使える）。

## 開発するとき

```bash
python3 -m http.server 5173
```

http://localhost:5173 を開く。localhost では Service Worker も動くので、
公開時とほぼ同じ条件で確認できる。編集したら:

```bash
git add -A && git commit -m "変更内容" && git push
```

※ `index.html` を直接ダブルクリックしても動くが、その場合 Service Worker と
manifest は読み込まれない（機能そのものには影響しない）。

## デザイン

`~/claude/subscriptions`（サブスク・固定費マネージャー）と同じデザイン言語を使っている。

- **余白**は4の倍数のみ（`--s1`..`--s8`）。中間値を作らない
- **文字**は6段階のみ（`--t-xs` 11px ..`--t-2xl` 48px）。1px刻みは使わない
- **角丸**は3種類（`--r-sm` / `--r-md` / `--r-lg`）
- **面**は「地(`--bg`)」と「板(`--panel`)」の2枚だけ。影に頼らず1pxの境界で分ける
- **文字色**は3段階（`--ink` / `--ink-2` / `--ink-3`）
- **アイコン**は16pxの線画（`viewBox="0 0 16 16"`, `stroke-width="1.3"`, `currentColor`）。
  絵文字は使わない（OSごとに描画が変わり制御できないため）
- 数字には `font-variant-numeric: tabular-nums` を当てて桁を揃える

種目の図解だけは独自で、`--ink-3`＝マシンの骨格、`--ink`＝人、`--accent`＝動く部分。

## ファイル構成

- `index.html` — アプリ本体（HTML / CSS / JS すべて）
  - 画面切り替えは History API に積んでいる。マウスのサイドボタン、ブラウザの
    戻る/進む、Mac のスワイプがそのまま画面移動になる。ポップアップも履歴に乗るので、
    戻る操作では「閉じるだけ」で下の画面は作り直さない。
    保存後のホームは `replaceState` にして、記録済みの画面へは戻らないようにしている
  - 記録画面の入力内容は画面を離れても保持される（同じメニューに戻れば続きから入力できる）。
    別のメニューを開こうとしたときだけ破棄の確認を出す
  - 画面は ホーム / 記録 / 履歴 / 設定 の4つ。設定はヘッダーの ⚙ から開く
    （ジムで開いたときにメニュー選択だけが見えるようにするため）
  - 画面遷移は macOS/iOS 風。ホームを起点(深さ0)、その先を(深さ1)として
    進む＝右から、戻る＝左から入る。
    ポップアップは macOS のシートのように上から降りて、閉じるときも縮んで消える。
    速さとイージングは `index.html` の `:root` にまとめてある:
    `--anim`（既定 .6s）、`--anim-fast`（.45s）、`--ease`（`cubic-bezier(.32,.72,0,1)`）。
    ここだけ変えれば全体の印象が変わる。
    `prefers-reduced-motion: reduce` の環境では全て無効になる
- `manifest.json` — ホーム画面に追加したときの名前・アイコン・表示設定
- `sw.js` — オフライン用の Service Worker（ネットワーク優先 + キャッシュ）
- `firebase-sync.js` — クラウド同期（Firestore + Googleログイン）
- `firestore.rules` — Firestore のセキュリティルール（Firebaseコンソールに貼る内容）
- `icons/` — アプリアイコン。サブスク側と同じ意匠（`#6969E0`→`#504AC9` の縦グラデーション、
  角丸半径 23%、白い字形を中央に大きく）。iOS はホーム画面のアイコンを強くキャッシュするので、
  差し替えるときは **ファイル名ごと変える**（`-v2` → `-v3`）。
  `icon-maskable-512-v2.png` は OS 側が円などで切り抜くため、角丸なしで字形を小さめにしている
  - `MENUS` … 種目マスタ。種目の追加・変更はここを編集する
  - `STORAGE_KEY` … localStorage のキー
  - 画面は `renderHome()` / `renderWorkout()` / `renderHistory()` の3つ

## データの保存とバックアップ

記録と写真は `localStorage` に入るので、**ブラウザごと・端末ごとに別々**になる。
iPhoneのChromeとPCのChromeも別物（Chromeアカウントの同期対象外）。
そのため、**記録をつける端末とブラウザは1つに固定する**のが前提。

刻み幅（`workout-steps-v1`）、体重（`workout-bodyweight-v1`）、表示テーマ（`workout-theme-v1`）は
端末ごとのローカル設定で、クラウド同期の対象外。

**表示テーマ**は 自動（OSに従う）/ ライト / ダーク の3択。CSS変数を
`:root`（ライト）、`@media (prefers-color-scheme: dark) の :root:not([data-theme="light"])`、
`:root[data-theme="dark"]` の3か所で定義し、明示指定がOSの設定より優先されるようにしている。
描画前にちらつかないよう、`<head>` のインラインスクリプトで最初に `data-theme` を当てている。

起動時に `navigator.storage.persist()` でブラウザに永続化を申請している。
Chromeはインストール済み（ホーム画面に追加済み）のサイトには基本的に許可する。

移行やバックアップはホーム画面の「データ」から:

- **書き出し** — `workout-backup-YYYY-MM-DD.json` を保存
- **読み込み** — 書き出したファイルを選ぶと**マージ**される（同じidの記録は重複しない、
  今ある記録は消えない）

### 記録データの形

```js
{
  id: 1787906281095,                    // 作成時刻（Date.now()）。編集しても変わらない
  date: "2026-08-28",
  savedAt: "2026-08-28T08:38:01.095Z",  // 最初に保存した時刻
  editedAt: "2026-08-28T08:38:04.099Z", // 編集して更新した時刻（編集していなければ無い）
  menu: "A",
  memo: "",
  exercises: [ /* ... */ ]
}
```

編集は既存のレコードを id で見つけて上書きするだけで、新しい記録は増えない。
`savedAt` は保ったまま `editedAt` だけを足すので、「いつ初めて記録したか」は残る。

### クラウド同期

Googleでログインすると、Firestore を経由して端末・ブラウザをまたいで同期される。

- 保存先: `users/{uid}/logs/{記録id}` と `users/{uid}/photos/{種目名}`
- 記録を保存・削除するたびに自動で同期。手動の「今すぐ同期」もある
- 方式は**マージ**（クラウドと端末で足りないものを互いに補う）。
  削除は `workout-deleted-v1` に id を残して、同期で復活しないようにしている
- セキュリティルールは `firestore.rules`。**ログインした本人のデータだけ**読み書きできる
- SDKの読み込みに失敗しても（オフラインなど）、アプリ本体はローカル保存だけで動く

`firebase-sync.js` の `firebaseConfig` は公開情報。安全性はルールとログインで担保している。
